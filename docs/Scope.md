# ขอบเขตโครงงาน

## ผู้ใช้งาน
นิสิต: สมัครบัญชีด้วย Student ID 10 หลักและรหัสผ่าน ใช้ได้ทันทีโดยไม่รออนุมัติ สลับภาษาไทย/อังกฤษได้ทุกหน้า ดูสถานะวันนี้ เลือกวันจองตั้งแต่วันนี้ถึง 30 วัน เลือกคอร์ด/เวลา ยืนยันผู้เล่นอีกคนด้วย Student ID ที่มีบัญชี active ดูประวัติ ยกเลิก และสนับสนุนค่าบำรุงสนามแบบไม่บังคับ

เจ้าหน้าที่: เข้าสู่ระบบแยกจากบทบาทนิสิต จัดการ Facility Schedule ทั้งวันนี้และวันอื่น ปรับสถานะคอร์ด ดู/ยกเลิกการจอง ดูรายงานรายวันตามวันที่จอง (จำนวน booking จำนวนคอร์ดที่ถูกใช้ รายการยกเลิก และทิป) และ audit log

## กฎธุรกิจ
1. หน้าหลักแสดง Facility Schedule ของวันนี้ตามเวลา Asia/Bangkok; การจองเลือกได้ตั้งแต่วันนี้ถึง 30 วัน
2. ไม่พบตาราง, สนามปิด, มีชื่อกิจกรรม, คอร์ดไม่ ACTIVE หรือ slot ไม่ active → ห้ามจอง
3. สมัครด้วย Student ID ตัวเลข 10 หลักและรหัสผ่าน; สมัครแล้ว active ทันที ไม่มี approval workflow
4. Student ID จาก session เป็นผู้จองหลักเท่านั้น ผู้จองคนที่สองต้องเป็น ID อีกคนที่ active และห้ามซ้ำกับบัญชีผู้จอง
5. Court + BookingDate + Slot มี BOOKED ได้เพียงหนึ่งรายการ; CANCELLED ไม่ยึด slot
6. Cancel เก็บประวัติ การ DELETE จะเปลี่ยนเป็น cancellation ผ่าน trigger
7. เงินสนับสนุน >0 ถึง 100,000 บาท ทศนิยม 2 ตำแหน่ง สำหรับ BOOKED เท่านั้น ไม่มี gateway จริง; Admin รายงานเงินตามวันที่จอง
8. ปิดสนามไม่ยกเลิกรายการเก่าอัตโนมัติ เจ้าหน้าที่จัดการ cancellation เองได้
9. Admin API ต้องการ role ADMIN; บัญชีนิสิตได้รับ role STUDENT และใช้ admin operations ไม่ได้

## ภายในขอบเขต
5 คอร์ด, 4 slot 18:00–22:00, 8 ตาราง, 3 views, 2 functions, 3 procedures, 2 triggers, transaction + indexes, reports, เอกสารรายงาน และ Thai/English UI

## ภายนอกขอบเขต
KU SSO/ตรวจทะเบียนจริง, payment จริง, notification, คิดค่าเช่าสนาม, AI และระบบแข่งขัน

การตรวจรหัสนิสิตไม่เชื่อมระบบทะเบียน KU จึงยืนยันได้เพียงรูปแบบ 10 หลักและสถานะบัญชีในระบบเดโม ไม่ใช่การพิสูจน์ตัวตน production
